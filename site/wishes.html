Everything else on this page tries to be neutral. This section does not. It collects what I would like cloud native operating systems to accomplish, as a group, over the next few years. You should know where I stand: I am one of the Kairos maintainers and I work for Spectro Cloud, so read this with that in mind. These are wishes for the whole field, not a description of any one project. Nothing here is used to rank the entries, and no project has to agree with it.

Reconcile the OS the way Kubernetes reconciles an app

When you deploy an app on Kubernetes, you declare what you want and a controller keeps it that way. If a pod dies, it gets replaced, and a new replica gets the same spec. The OS is often handled differently. In many setups an upgrade is something you trigger, and it runs once. Some tools do keep nodes up to date on their own, but they often follow the latest release on a channel, not a version you declared next to your apps. Whether a node that joins later, or one that rolled back, ends up on the version you wanted depends on the tool you picked.

I would like the OS to be part of the same loop as the apps. You declare the OS version a group of nodes should run, and something keeps them there. Then, when an app needs a newer kernel or a new driver, you could ship the OS change and the app change together, and the cluster would converge on both, OS first. That would close much of the gap between the OS and the platform on top of it. Some projects already get part of the way there, inside Kubernetes or outside it.
